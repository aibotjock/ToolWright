# Code of Conduct

## The short version

Be decent. Assume good faith. Argue about the work, not the person.

## Expected behaviour

- Engage with technical substance. Strong disagreement is welcome; contempt is
  not.
- Accept that maintainer time is finite and unpaid. A closed issue is not an
  insult.
- Report problems clearly enough that someone can act on them.
- Respect the licensing constraints described in `CONTRIBUTING.md`, even if you
  disagree with them.

## Unacceptable behaviour

- Harassment, insults, or personal attacks.
- Discriminatory language or conduct.
- Publishing others' private information without permission.
- Deliberately posting security vulnerabilities publicly to force a response.
- Sustained disruption of discussions.

## Scope

Applies to all project spaces — issues, pull requests, discussions, and commit
messages — and to public conduct that plausibly represents the project.

## Enforcement

Report concerns to the maintainer via
[private vulnerability reporting](https://github.com/aibotjock/ToolWright/security/advisories/new)
or a direct message on GitHub. Reports will be handled discreetly.

Responses range from a warning to a permanent ban, at the maintainer's
discretion. The project is currently maintained by one person; there is no
appeals committee, and none is claimed.

## Note

This is a deliberately short, plain policy rather than an adopted external
covenant, chosen because a single maintainer can honestly commit to enforcing
it. If the project grows a contributor community, it should be replaced with a
standard covenant and a named enforcement contact — tracked in
`GOVERNANCE.md`.
